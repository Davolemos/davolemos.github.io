# Checklist y errores frecuentes

Usa este archivo para auditar y validar. Marca cada punto como ✅ cumple, ⚠️ parcial, ❌ no cumple o ⏳ pendiente de prueba física / con usuarios.

## Errores frecuentes

| Error                                             | Por qué falla                                                                     | Corrección                                   |
|---------------------------------------------------|-----------------------------------------------------------------------------------|----------------------------------------------|
| Usar una “fuente disléxica” y no cambiar nada más | La fuente por sí sola no resuelve jerarquía, lenguaje ni contraste                | Diseñar el sistema completo y probarlo       |
| Abrir demasiado el tracking                       | Puede separar visualmente las letras de una palabra y ralentizar a otros lectores | Ajuste moderado y pruebas comparativas       |
| Escribir todo en mayúsculas                       | Elimina variedad de siluetas y densifica el bloque                                | Mayúscula/minúscula y énfasis en negrita     |
| Colocar texto sobre fotografías                   | Produce contraste variable y ruido                                                | Zona sólida o placa de lectura               |
| Distinguir sabores solo por color                 | Falla con daltonismo, baja luz o memoria del color                                | Nombre + icono + patrón/imagen               |
| Usar demasiados claims                            | Obliga a buscar sin saber qué es prioritario                                      | Uno o dos claims frontales                   |
| Reducir texto hasta el mínimo legal               | Cumple parcialmente, pero puede seguir siendo difícil de leer                     | Superar mínimos cuando sea viable            |
| QR sin explicación                                | El usuario desconoce qué obtendrá                                                 | Etiqueta de acción y beneficio               |
| Diseñar un solo SKU                               | La accesibilidad se rompe al extender la familia                                  | Probar arquitectura multivariante            |
| Validar solo con el equipo creativo               | Reproduce supuestos internos                                                      | Co-diseñar y ensayar con usuarios disléxicos |

## Checklist final

### Branding
- [ ] El nombre se pronuncia y recuerda fácilmente.
- [ ] El descriptor explica literalmente la categoría.
- [ ] El wordmark funciona a tamaño pequeño.
- [ ] Los caracteres similares se distinguen.
- [ ] La fuente expresiva no invade información funcional.
- [ ] El tono usa frases cortas, voz activa y vocabulario común.
- [ ] Existen reglas de accesibilidad dentro del brand book.

### Empaque
- [ ] Se identifica marca, producto y variante en pocos segundos.
- [ ] La variante no depende solo del color.
- [ ] La información tiene un orden predecible.
- [ ] El texto esencial está alineado a la izquierda y sin justificar.
- [ ] No hay frases largas en mayúsculas, cursiva o tipografía condensada.
- [ ] El contraste fue medido y también probado físicamente.
- [ ] No hay texto crítico sobre imágenes, reflejos, pliegues o transparencias.
- [ ] Las instrucciones usan verbo, número e icono cuando corresponde.
- [ ] Apertura y cierre están señalizados exactamente donde ocurren.
- [ ] El QR explica su función y abre contenido accesible.
- [ ] Las exigencias legales del mercado fueron verificadas por separado.

### Validación
- [ ] Participaron adultos con dislexia en etapas tempranas y finales.
- [ ] Se probaron varias opciones, no una única solución.
- [ ] Se midieron errores, tiempo, comprensión y recuerdo.
- [ ] El empaque se evaluó en anaquel, en mano y bajo distintas luces.
- [ ] Se ensayaron al menos tres variantes juntas.
- [ ] Se revisó una muestra impresa sobre el material final.
